## 概述：CS50 作业设计哲学

CS50 的作业不是"填代码坑"——而是**每个作业都让你从零实现一个完整程序的核心逻辑**。其设计遵循几个原则：

1. **先 Lab 后 PSet**：Lab 是脚手架，在简单的环境中练习当周核心概念；PSet 是挑战，让你独立解决问题
2. **分层难度**：每个 PSet 都提供 "less comfortable" 和 "more comfortable" 两个版本，允许学生根据自身水平选择
3. **真实场景**：问题取材于现实世界——信用卡验证、图像处理、拼写检查、股票交易
4. **渐进式复杂度**：从打印 "hello, world" 到构建完整的 Web 应用，10 周走完一个程序员的能力成长曲线
5. **工具链教育**：在专业 Linux 环境（Codespace）中使用 `make`、`check50`、`style50`、`debug50` 等工具，培养工程习惯

## Week 0 — Scratch

### Problem Set 0: Scratch Project

**你要做什么：**

用 MIT Scratch（可视化编程）创作一个交互式项目——可以是游戏、动画、互动故事或艺术创作。

**核心知识点：**

| 概念 | 在 Scratch 中的体现 |
|------|---------------------|
| 顺序执行 | 积木块从上到下排列 |
| 循环 | `forever`、`repeat N` 块 |
| 条件分支 | `if/then/else` 块 |
| 变量 | `set [score] to 0`、`change [score] by 1` |
| 事件驱动 | `when green flag clicked`、`when key pressed` |
| 线程/并发 | 多个 sprite 同时运行各自的脚本 |
| 布尔逻辑 | `and`、`or`、`not` 操作符 |
| 消息传递 | `broadcast [message]` / `when I receive [message]` |

**常见坑 / CS50 特有约束：**

- 必须包含至少两个 sprite（精灵/角色）
- 必须使用至少一个条件、一个循环、一个变量
- 必须使用至少一个自定义 block（函数抽象）
- 项目复杂度与 Week 1-5 的代码作业相比看似"简单"，但这是精心设计的——让学生在接触文本代码前先建立程序思维

**设计亮点——为什么这个作业好：**

> Week 0 用 Scratch 让学生**不用写一行文本代码就能理解计算机科学的全部核心概念**。条件、循环、变量、事件——这些东西在 Scratch 里用积木块拖拽就能实现，完全消除了语法恐惧。当学生 Week 1 看到 C 语言的 `if`、`for`、`int x = 0` 时，他们已经理解了这些概念在做什么，只需要学习语法表达。

## Week 1 — C

### Lab 1: Population Growth

**你要做什么：**

模拟美洲驼（llama）种群增长。给定起始种群大小 `start` 和目标种群大小 `end`，每年有 `n/3` 只新生驼和 `n/4` 只驼死亡。计算需要多少年才能达到目标种群。

输入验证：`start` 必须 ≥ 9（否则种群无法维持），`end` 必须 ≥ `start`。

**核心知识点：**

- **`do...while` 循环**：至少执行一次，用于输入验证
- **整数除法（truncation）**：C 语言中 `n/3` 和 `n/4` 是整数除法，自动舍去小数部分
- **类型转换与溢出意识**：种群可能变得非常大，需要考虑 `int` 的范围
- **循环计数模式**：`years++` 在每次迭代中递增

**常见坑 / CS50 特有约束：**

- **"Are you a llama?" 验证**：如果用户输入 `start < 9`，程序必须提示并要求重新输入——这里必须用 `do...while` 而非 `while`，因为至少要问一次
- **整数除法陷阱**：新生驼 = `n / 3`（不是 `n * 0.33`），死亡驼 = `n / 4`。新手常误用浮点数或忘记 C 的截断行为
- **阈值判断**：当种群 ≥ `end` 时停止。注意要 `>=` 不是 `==`，因为种群可能跳超过目标值
- **空输入处理**：`get_int` 会自动拒绝非整数输入，但需要手动验证数值范围

**设计亮点：**

> 这个 Lab 巧妙地用种群增长模型教会了 `do...while` 循环的正确使用场景。很多教材只是说"do...while 先执行后判断"，但学生不知道为什么需要它。这里通过"至少问一次"的输入验证场景，让学生切身体会 `do...while` vs `while` 的区别，且只用了一个文件、几十行代码。

**你要做什么：**

#### Mario（嵌套循环）

**你要做什么：**

用 `#` 打印一个右对齐的金字塔，高度由用户输入（1-8 之间）。

```
       #
      ##
     ###
    ####
   #####
  ######
 #######
########
```

Less comfortable：如上。More comfortable：双金字塔（中间有间隙）。

**核心知识点：**

- **嵌套 `for` 循环**：外层控制行，里层控制每行的空格和 `#`
- **循环变量关系**：第 i 行有 `height - i` 个空格、`i` 个 `#`
- **输入验证**：用 `do...while` 确保输入在 1-8 之间
- **格式化输出**：`printf` 中不自动换行（不用 `\n` 在内部循环中）

**常见坑：**

- **索引混淆**：新手常把行号、空格数、`#` 数的关系搞反。关键洞察：第 i 行（从 1 开始）= `height - i` 空格 + `i` 个 `#`
- **循环范围**：`for (int j = 0; j < something; j++)` 中的边界条件，差 1 错误（off-by-one）是最常见的 bug
- **嵌套顺序**：必须先打印空格再打印 `#`，否则金字塔不对齐
- **换行时机**：每行结束时打印 `\n`，但空格和 `#` 之间不换行

**设计亮点：**

> Mario 是编程教学史上最经典的嵌套循环练习之一。它只用一种字符 `#`，却让学生必须理解**二维空间中的索引映射关系**。当你终于让金字塔对齐的那一刻，你对 `for` 循环的理解会从"语法"变为"空间思维"。More comfortable 版本的双金字塔进一步考验循环变量管理能力。

#### Cash（贪心算法）

**你要做什么：**

给定欠款金额（美分），用最少的硬币找零。硬币面额：25¢（quarter）、10¢（dime）、5¢（nickel）、1¢（penny）。

**核心知识点：**

- **贪心算法（Greedy Algorithm）**：每一步取最大可能值
- **整数除法和取模**：`cents / 25` 计算 quarter 数量，`cents % 25` 计算余数
- **累加模式**：`coins += quarters + dimes + nickels + pennies`
- **输入验证**：用户必须输入非负整数

**常见坑：**

- **浮点数陷阱**：CS50 特意强调——不要用 `float` 接收美元金额再乘以 100，因为浮点数不精确。直接用 `int` 接收美分数
- **取模 vs 减法**：两种实现方式——`cents = cents % 25` 或 `cents -= quarters * 25`。取模更优雅但新手常忘记
- **算法正确性保证**：美式硬币面额（1, 5, 10, 25）恰好保证贪心算法能得到全局最优解。如果换成其他面额组合（如 1, 3, 4），贪心可能失效——这是一个重要的计算机科学事实
- **零钱输入**：当 `cents = 0` 时，程序应输出 `0`（不需要任何硬币）

**设计亮点：**

> Cash 用一个日常生活场景（找零）引出计算机科学中最重要的算法设计范式之一——贪心算法。学生不需要知道"贪心"这个词也能理解 "每次用最大面额" 的策略。CS50 非常聪明地把理论概念藏在一个实际问题的解法里，等学生做完再告诉他们 "这其实是一个贪心算法"。

#### Credit（Luhn 算法）

**你要做什么：**

验证信用卡号码是否合法，并判断发卡机构（AMEX / MasterCard / VISA）。

**核心知识点：**

- **Luhn 算法**：校验和算法，银行系统广泛使用
  - 从倒数第二位开始，每隔一位乘以 2
  - 如果乘积 ≥ 10，取其各位数字之和
  - 所有数字（乘过的 + 没乘的）求和
  - 总和 % 10 == 0 则合法
- **数字位数计算**：不断 `n /= 10` 直到 `n == 0`
- **提取特定位**：`n % 10` 取个位，`n / 10` 去掉个位
- **长整数处理**：必须使用 `long`（64 位），因为 16 位卡号超出 `int` 范围
- **基于长度的判断**：AMEX 15 位，MC 16 位，VISA 13 或 16 位

**常见坑：**

- **`int` 溢出**：这是 CS50 让学生**第一次意识到 `int` 不够用**的时刻。信用卡号最多 16 位，而 `int` 只能存到约 21 亿（10 位）。必须用 `get_long()`
- **Luhn 算法的实现顺序**：CS50 的说明中 "Multiply every other digit by 2, starting with the number's second-to-last digit"——注意是**倒数第二位开始**，不是第一位
- **乘积 ≥ 10 的处理**：如 `7 * 2 = 14`，需要 `1 + 4 = 5`，不是直接用 14
- **AMEX 起始数字**：34 或 37。需要提取前两位来判断
- **只输出一个结果**：`AMEX\n` 或 `MASTERCARD\n` 或 `VISA\n` 或 `INVALID\n`——不能多输出任何东西

**设计亮点：**

> Credit 是 CS50 第一个真正有**算法深度**的作业。Luhn 算法看似复杂，但拆解后核心就是 "while 循环 + 取模运算"。它让学生接触到了真实世界的工业标准（每张信用卡都经过 Luhn 校验），同时锻炼了多重嵌套逻辑——先校验合法性，再判断卡类型，最后输出结果。这也为 Week 3 的算法学习埋下伏笔。

## Week 2 — Arrays

### Lab 2: Scrabble

**你要做什么：**

计算两个玩家输入的单词在 Scrabble（拼字游戏）中的得分。每个字母有固定分值（A=1, B=3, ... Z=10），不区分大小写。

**核心知识点：**

- **数组作为查找表（Lookup Table）**：`int POINTS[] = {1, 3, 3, 2, 1, ...}`
- **字符到数组索引的映射**：`toupper(c) - 'A'` 将字母映射到 0-25
- **字符串遍历**：`for (int i = 0, n = strlen(word); i < n; i++)`
- **`ctype.h` 函数**：`toupper()`、`tolower()`、`isalpha()`
- **ASCII 码的理解**：`'A'` 的数值是 65，`'a'` 是 97

**常见坑：**

- **非字母字符**：Scrabble 只给字母计分。如果用户输入了标点或数字，需要跳过（用 `isalpha()` 或 `isupper()`/`islower()`）
- **大小写**：`'a' - 'A' = 32`，直接做减法得到的是错误索引。必须统一大小写
- **数组越界**：如果忘记 `toupper()` 而直接 `word[i] - 'A'`，小写字母会得到 32+ 的索引

**设计亮点：**

> Scrabble 用一个有趣的游戏场景引入数组。这不是"学习数组语法"的枯燥练习，而是让学生发现**数组作为查找表**的自然用途。26 个字母对应 26 个分值——这是数组最经典、最直观的使用场景。同时隐含教授了字符编码知识（ASCII 偏移）。

### Problem Set 2: Readability / Caesar or Substitution

#### Readability（文本可读性）

**你要做什么：**

实现 Coleman-Liau 指数，评估一段英文文本的阅读难度等级。

公式：`index = 0.0588 * L - 0.296 * S - 15.8`

其中 L = 每 100 词的平均字母数，S = 每 100 词的平均句子数。

**核心知识点：**

- **字符分类**：`isalpha()` 判断字母，`isspace()` 判断空格，`ispunct()` 判断标点
- **句子边界检测**：以 `.` `!` `?` 作为句子结束标志
- **单词计数**：通过空格数 + 1 来估计单词数
- **浮点数运算与取整**：用 `round()` 取整到最近的整数
- **条件分支**：根据 index 输出 "Before Grade 1" 到 "Grade 16+"

**常见坑：**

- **句子检测的边界情况**：`...`（省略号）、`Mr.`（缩写中的句号）可能被误判为句子结束。CS50 的测试数据避免了这些复杂边界，但仍需注意
- **单词计数**：连续空格、前导空格会影响单词计数。更好的做法是检测从非空格到空格的转换
- **整数除法的陷阱**：`L` 和 `S` 的计算涉及乘法后除以单词数。C 中如果先做整数除法会丢失精度，必须先转换为 `float`
- **输出格式**：`Grade X`（X 是整数），或 `Before Grade 1`、`Grade 16+`

**设计亮点：**

> Readability 把学生从纯数学领域拉到自然语言处理（NLP）的门口。计算文本可读性听起来很深奥，但其实只是**统计字母、单词、句子数量**然后套公式。CS50 用这种方法告诉学生：很多看似高深的算法，核心其实是简单统计+公式。同时也是一次 C 语言字符处理能力的全面练习。

#### Caesar（凯撒密码）

**你要做什么：**

用命令行参数接收一个密钥 `k`（非负整数），然后对用户输入的明文进行凯撒加密——每个字母向后移动 `k` 个位置，保持大小写，非字母不变。

**核心知识点：**

- **命令行参数**：`int main(int argc, string argv[])`，`argc` 是参数数量，`argv` 是参数字符串数组
- **参数验证**：检查 `argc == 2`，验证 `argv[1]` 的每个字符都是数字
- **模运算（Modular Arithmetic）**：`(c - 'A' + k) % 26 + 'A'` ——这是密码学的基础数学工具
- **`atoi()`**：将字符串转为整数
- **字符串遍历与条件修改**

**常见坑：**

- **命令行参数数量检查**：必须确保 `argc == 2`，否则程序应返回 1 并提示用法
- **`argv[1]` 必须是纯数字**：需要遍历验证每个字符都是 `isdigit()`，否则返回 1
- **大密钥处理**：`k` 可能大于 26，需要用 `k % 26` 缩减。如果没有这一步，`'z' + 27` 会超出字母范围
- **大小写保持**：需要分别处理大写字母（`'A'` 为基准）和小写字母（`'a'` 为基准）
- **非字母不修改**：空格、标点、数字原样输出

**设计亮点：**

> Caesar 引入了一个新维度——**命令行参数**。在此之前所有交互都是运行时 `scanf`/`get_string`，现在学生理解到程序可以在启动时接收参数。同时模运算（`% 26`）的应用巧妙展示了数学在编程中的力量。密码学背景也给这个算法练习增添了趣味性。

#### Substitution（替换密码）

**你要做什么：**

用命令行参数接收一个 26 字母的密钥（每个字母唯一，对应 A-Z 的替换映射），然后对用户输入的明文进行替换加密。保持大小写，非字母不变。

**核心知识点：**

- **单向映射**：建立 `plaintext[i]` → `ciphertext[i]` 的映射关系
- **密钥验证**（多重验证）：
  - 恰好 26 个字符
  - 每个字符都是字母
  - 每个字母只出现一次（无重复）
- **大小写保持**：如果明文是大写，密文也是大写（`toupper`/`tolower`）
- **重复检测算法**：遍历密钥，用布尔数组标记已出现的字母

**常见坑：**

- **密钥验证顺序**：CS50 测试要求按特定顺序验证——先长度，再是否全字母，再唯一性
- **重复检测**：新手常用 O(n²) 的双重循环来检测重复。更优的方式是用一个 26 元素的 `bool` 数组
- **大小写映射**：明文 'A' 映射到 `key[0]` 的大写，明文 'a' 映射到 `key[0]` 的小写
- **命令行参数错误时的返回值**：必须 `return 1`，不是随便 `printf` 一条错误信息就行

**设计亮点：**

> 从 Caesar（单一偏移量）到 Substitution（任意映射），这是密码学难度的一次跳跃。密钥验证本身就是一个**多步骤算法设计练习**——需要检查长度、字符类型、唯一性。26 个字母不重复的要求让学生自然地发现布尔数组的去重用途。More comfortable 版本相对于 Caesar 相当于从 O(1) 密钥空间（26 种可能）跃升到 O(26!) 密钥空间。

## Week 3 — Algorithms

### Lab 3: Sort

**你要做什么：**

分析三种排序算法（Selection Sort、Bubble Sort、Merge Sort）在不同输入（已排序、逆序、随机）下的运行时间。通过实际计时代码，直观感受 O(n²) vs O(n log n) 的差异。

**核心知识点：**

- **时间复杂度实证分析**：不是从理论上推导，而是**实际运行和计时**
- **排序算法的行为差异**：
  - Selection Sort：总是 O(n²)，即使已经排序
  - Bubble Sort：最好情况 O(n)（已排序时提前终止），最坏 O(n²)
  - Merge Sort：总是 O(n log n)
- **`clock()` 计时**：`(end - start) / CLOCKS_PER_SEC`
- **数据规模对算法选择的影响**：小数据集上 O(n²) 可能比 O(n log n) 快（常数因子小）

**设计亮点：**

> 这个 Lab 的精妙之处在于——它**不说教**，让你**自己看**。学生亲手计时后会震惊地发现：Merge Sort 在 10000 个元素时几乎瞬间完成，而 Selection Sort 需要好几秒。这种亲眼所见的冲击力远比教科书上的数学推导更有说服力。

### Problem Set 3: Plurality / Runoff or Tideman

#### Plurality（简单多数投票）

**你要做什么：**

实现简单多数投票制——每个选民投一票，得票最多的候选人获胜。如有平局，输出所有平局者。

**核心知识点：**

- **结构体（`struct`）**：`candidate` 结构体包含 `name` 和 `votes`
- **线性搜索**：在候选人数组中搜索名字
- **找最大值**：遍历 `votes` 数组，跟踪最大值
- **平局处理**：多个候选人可能同时有最高票数

**常见坑：**

- **`struct` 数组操作**：`candidates[i].votes++` vs `candidates[i]->votes++`（取决于传参方式）
- **字符串比较**：必须用 `strcmp()` 而非 `==`
- **最大值更新**：找到更大的票数时，之前的平局候选人都要清除

**设计亮点：**

> Plurality 是 Week 3 的 "less comfortable" 起点。它自然地引出 `struct` 这个新概念——一个候选人有名字和票数，这就是 `struct` 最直观的使用场景。同时平局处理让学生思考 "有多个最大值时怎么办" 这种边界情况。

#### Runoff（排序复选制 / Instant Runoff）

**你要做什么：**

实现即时决选制（IRV）。选民对候选人排序（1st, 2nd, 3rd...）。每轮淘汰得票最少的候选人，将其选票转给下一选择，直到有人获得过半数。

**核心知识点：**

- **二维数组**：`preferences[voter][rank]` ——第 i 个选民的第 j 选择
- **淘汰逻辑**：找最小值，标记淘汰，重新分配选票
- **多轮迭代**：循环直到有人获得 > 50% 选票
- **过半数检测**：`votes > voter_count / 2`

**常见坑：**

- **已淘汰候选人的选票重分配**：被淘汰的候选人不能再获得选票，需要跳到选民的下一选择
- **所有候选人平票**：如果所有剩余候选人票数相同，宣布平局
- **最小值是 0**：如果某人 0 票且不是最小值，要区分 "0 票" 和 "被淘汰"
- **重分配时机**：必须在淘汰之后、下一轮投票之前

**设计亮点：**

> Runoff 比 Plurality 多了一个维度——**排名**。学生从一维投票（名字→票数）进入到二维投票（选民→排名→候选人）。淘汰和重分配的循环逻辑是多轮状态管理的经典练习。同时 Runoff 让学生理解：现实中爱尔兰、澳大利亚等国就用的这种制度。

#### Tideman（最大成对决胜制 / Ranked Pairs）

**你要做什么：**

实现 Tideman 投票法（又名 Ranked Pairs）。这是 CS50 公认**最难的 PSet**。核心流程：

1. **Tally**：对每对候选人，统计多少人偏好 A 胜过 B → 建立 `preferences[i][j]` 矩阵
2. **Sort**：将所有候选人对按胜率差从大到小排序
3. **Lock**：依次锁定胜率差最大的边，但如果某条边会造成**环路**（cycle），则跳过
4. **Winner**：图的源点（没有任何箭头指向它的候选人）即为赢家

**核心知识点：**

- **图论（Graph Theory）**：候选人作为节点，胜出关系作为有向边
- **邻接矩阵（Adjacency Matrix）**：`locked[i][j] = true` 表示 i→j 有边
- **环路检测（Cycle Detection）**：递归 DFS 检查是否存在从 loser 到 winner 的路径（这恰恰构成了环路）
- **排序**：对 `pair` 结构体按 `margin` 降序排列
- **二维数组的深层操作**：`preferences[i][j]` 和 `locked[i][j]` 的交叉使用

**常见坑：**

- **环路检测递归**：`bool cycle(int winner, int loser)` ——从 loser 出发，如果能走到 winner，加锁这条边就会形成环路。这是 DFS 的经典应用，但新手极难独立想出
- **`preferences` 的对称性**：`preferences[i][j] + preferences[j][i] = voter_count`
- **排序稳定性**：`sort_pairs` 不需要稳定排序，但 CS50 测试预期按 `margin` 降序
- **多候选人场景**：5 个候选人 = 10 个 pair，需要全部排序和加锁
- **平局处理**：如果两个候选人的 `preferences[i][j] == preferences[j][i]`，这个 pair 不应被加入
- **Rekey 函数**：`add_pairs` 中需要更新 `pair_count` 全局变量

**设计亮点：**

> Tideman 是 CS50 的 "终极 Boss"。它在一个问题里集成了：**图论、递归、排序、二维数组、结构体、DFS**。如果学生能独立完成 Tideman（不是抄答案），意味着他们对数据结构 + 算法的理解已经超越了大多数计算机专业大一学生的水平。CS50 把它放在 "more comfortable" 位置非常明智——不是强制的，但完成后会给学生巨大的信心飞跃。

### Lab 4: Volume

**你要做什么：**

修改 WAV 音频文件的音量。读取输入的 WAV 文件，将每个音频采样的值乘以一个缩放因子，写入输出文件。

**核心知识点：**

- **文件 I/O**：`fopen(f, "r")` / `fopen(f, "w")`，`fread()`，`fwrite()`，`fclose()`
- **二进制文件结构**：WAV 文件的 44 字节头部（header）+ 音频采样数据
- **`uint8_t`、`int16_t`**：精确宽度整数类型（`stdint.h`）
- **字节级别的数据处理**：`fread(&buffer, sizeof(int16_t), 1, input)`
- **文件头部的保护**：WAV 头部不应被修改，只修改采样数据

**常见坑：**

- **WAV 头部大小**：恰好 44 字节。必须原样复制 header，不能修改（否则文件损坏）
- **`int16_t` 的范围**：16 位有符号整数，范围 [-32768, 32767]。缩放后可能溢出
- **`fread` 返回值检查**：`fread` 返回实际读取的元素数，不应该假设一定成功
- **文件打开模式**：input 用 `"r"`（文本模式）即可，但理论上二进制更安全 `"rb"`
- **`fwrite` 写入 header**：`fwrite(header, sizeof(uint8_t), HEADER_SIZE, output)` ——注意参数顺序：buffer → size → count → file

**设计亮点：**

> Volume 是 CS50 中第一个直接操作**二进制文件**的练习。在此之前所有数据都是终端文本 I/O。WAV 格式设计精巧——44 字节头部恰好足够描述音频元数据。通过这个 Lab，学生建立起文件格式、指针、内存、字节这些底层概念的直观联系。

### Problem Set 4: Filter / Recover

#### Filter（BMP 图像滤镜）

**你要做什么：**

对 BMP 位图文件应用图像滤镜。实现四个滤镜：
- **Grayscale（灰度）**：每个像素 RGB 取平均值
- **Sepia（复古棕褐）**：应用 sepia 公式变换 RGB
- **Reflect（水平翻转）**：左右镜像
- **Blur（模糊/方框模糊）**：每个像素取周围 3×3 邻域的平均

**核心知识点：**

- **BMP 文件格式**：`BITMAPFILEHEADER`（14 字节）+ `BITMAPINFOHEADER`（40 字节）+ 像素数据
- **像素数组遍历**：`image[i][j].rgbtRed/Green/Blue`
- **结构体**：`RGBTRIPLE` 包含三个 `BYTE`（即 `uint8_t`）
- **2D 卷积**（Blur）：3×3 核在图像上滑动
- **原地修改 vs 临时副本**：Blur 需要先复制原图到临时数组，否则修改过的像素会影响后续像素的模糊计算
- **边界处理**：边缘像素的邻域不完整（如左上角只有 4 个邻居）
- **值域裁剪**：Sepia 公式产生的值可能超过 255，需用 `fmin(255, value)`

**常见坑：**

- **BMP 的 padding**：每行像素数据的字节数必须是 4 的倍数。如果宽度不是 4 的倍数，每行末尾有 0-3 字节的 padding
- **像素大小**：24-bit BMP 每个像素 3 字节（RGB）
- **Blur 中的临时副本**：**这是最经典的坑**。如果直接原地修改，模糊第 2 行第 3 列的像素时会用到已经模糊过的第 1 行像素。必须 `memcpy` 一份原图
- **整数除法截断**：灰度平均 `(R+G+B)/3` 用整数除法会截断，得到偏暗的图像。如果要求四舍五入，需要 `(R+G+B+1)/3` 或 `round((float)(R+G+B)/3)`
- **Sepia 溢出**：R/G/B 分量各自独立计算，每个都可能 > 255
- **Reflect 的中间值**：如果只交换到一半就停下，`temp = left; left = right; right = temp` 用三个变量

**设计亮点：**

> Filter 让学生亲手实现 Instagram 级别的图像处理。BMP 是一个简单到可以在一个课堂上讲清楚的格式，同时足够真实。Blur 中的"必须创建临时副本"是一个微妙的陷阱，教会学生**副作用（side effect）** 这个概念。当一个操作改变了它正在读取的数据时，算法逻辑就会悄然崩塌——这是所有程序员都会在职业生涯中反复遇到的核心教训。

#### Recover（JPEG 恢复）

**你要做什么：**

从一个 FAT 文件系统的原始镜像（`card.raw`）中恢复被删除的 JPEG 照片。JPEG 文件以特定的字节签名（`0xff 0xd8 0xff 0xe0`-`0xef`）开始，以 512 字节块存储。

**核心知识点：**

- **文件签名（Magic Bytes）**：JPEG 的前三个字节 `0xff 0xd8 0xff` + 第四个字节 `0xe0`-`0xef`
- **FAT 文件系统**：文件以 512 字节块（簇）为单位存储，删除后数据仍在但目录项消失
- **`fread` 循环模式**：每次读 512 字节到 `uint8_t buffer[512]`
- **动态文件管理**：`fopen` 新文件、`fwrite` 数据、`fclose` 旧文件
- **状态机思维**：跟踪"当前是否正在写入一个 JPEG"
- **文件命名**：`###.jpg`（`sprintf(filename, "%03i.jpg", counter)`）

**常见坑：**

- **签名检测的条件组合**：`buffer[0] == 0xff && buffer[1] == 0xd8 && buffer[2] == 0xff && (buffer[3] & 0xf0) == 0xe0`
- **第一个 JPEG 开始前**：card.raw 开头可能有一些非 JPEG 数据（FAT 元数据等），需要跳过直到发现第一个签名
- **文件边界**：JPEG 在 FAT 文件系统中是连续存储的（CS50 保证），所以一个新签名 = 上一个文件的结束 + 新文件的开始
- **`fclose` 时机**：在打开新文件前必须先关闭旧文件。最后一个 JPEG 在循环结束后也要关闭
- **文件计数器**：从 000 开始（`000.jpg`）

**设计亮点：**

> Recover 是一个迷你版的数字取证（digital forensics）练习。你手上只有一个原始磁盘镜像，没有目录、没有文件名——你要像法医一样从一团二进制数据中"复活"照片。这教会学生：**文件只是磁盘上的字节序列**，文件系统只是组织这些字节的索引。FAT 块对齐的设计让问题足够简单（512 字节正好够你读懂），但又足够真实（数据恢复工具就是这样工作的）。完成后你手里突然多出 50 张 JPEG——那个瞬间的成就感无与伦比。

## Week 5 — Data Structures

### Lab 5: Inheritance

**你要做什么：**

模拟遗传学中的血型遗传。创建一个家族树，每个人有两个父母（通过 `malloc` 创建），随机分配血型等位基因（A、B、O），按孟德尔遗传规律从父母各继承一个等位基因。

**核心知识点：**

- **动态内存分配**：`malloc(sizeof(person))`
- **结构体指针**：`person *parent = malloc(sizeof(person))`
- **递归结构体**：`person` 包含 `person *parents[2]`
- **随机数**：`rand()` 的使用
- **树的遍历**：递归 free 家族树内存（后序遍历）
- **内存释放**：`free()` 防止内存泄漏

**常见坑：**

- **忘记 `malloc`**：不能直接声明 `person parent` 然后赋值给 `child->parents[0]`，函数返回后栈内存就失效了
- **`free` 的时机和顺序**：必须**自底向上** free（先 free 子节点，再 free 父节点），否则丢失子节点指针造成泄漏
- **血型逻辑**：等位基因组合的对应关系——AA/AO→A，BB/BO→B，AB→AB，OO→O
- **NULL 检查**：malloc 可能返回 NULL（内存不足），要检查
- **随机种子**：需要 `srand(time(NULL))` 否则每次运行结果相同

**设计亮点：**

> Inheritance 在一个问题里优雅地集成了三个核心概念：**指针、动态内存、递归结构**。家族树是递归定义（每个人都有父母，父母也是人）的自然范例。`malloc` 和 `free` 的配对让学生直观理解 "谁分配谁释放" 的内存管理责任——这是 C 语言最独特（也最危险）的特性。

### Problem Set 5: Speller（拼写检查器 / 哈希表）

**你要做什么：**

这是 CS50 唯一的一个"给定框架 + 只实现核心"的 PSet。给定 `speller.c`（主程序）、`dictionary.h`（接口）、`dictionary.c`（骨架），你需要实现哈希表中的五个函数：

- `load()`：从字典文件加载 143,091 个单词到内存哈希表
- `hash()`：将单词映射到 0 到 N-1 的桶索引
- `check()`：检查一个单词是否在字典中（大小写不敏感）
- `size()`：返回字典中的单词总数
- `unload()`：释放所有动态分配的内存

CS50 的 `speller` 程序会对你的实现进行**实际性能基准测试**。

**核心知识点：**

- **哈希表（Hash Table）**：链地址法（chaining）——每个桶是一个链表头
- **链表操作**：头插法（在桶的头部插入新节点）效率最高
- **哈希函数设计**：`hash("cat")` → 0..N-1。可以基于第一个字母、字母和、或更复杂的分布
- **字符串大小写处理**：`tolower()` 或 `strcasecmp()`
- **`const` 关键字**：`const char *word` 表示不能修改传入的字符串
- **性能优化思维**：理论上 O(1) vs 实际上墙钟时间（wall-clock time）的差异
- **`valgrind` 内存检测**：检查内存泄漏

**常见坑：**

- **链表头插法的指针顺序**：`new_node->next = table[index]; table[index] = new_node;`（顺序错了会丢失链表）
- **`N`（桶数量）的选择**：默认 26（对应首字母）太小了。哈希表负载因子 = 单词数 / N，负载因子越大，链表越长，查找越慢。增加到 65536 或更大能显著提升性能
- **大小写不敏感**：字典中所有单词是小写。检查时要将待查单词 `tolower()` 后再比较
- **哈希函数质量**：如果 `hash` 返回的分布不均匀（如 90% 的单词聚在 5 个桶里），查找很慢
- **`unload()` 中的双重循环**：外层遍历 N 个桶，内层遍历链表。每个节点都要 `free`，且不能丢失 `next` 指针
- **`strcmp` vs `strcasecmp`**：后者是大写不敏感的比较，但 CS50 库可能不包含，需自行实现
- **字典中单词的最长长度**：`LENGTH = 45`，分配节点时用 `char word[LENGTH + 1]`

**设计亮点：**

> Speller 是 CS50 作业设计的巅峰之一。它有几个精妙之处：
>
> 1. **给定框架、只写核心**：学生不需要处理文件 I/O、命令行解析、计时统计——这些 CS50 已经写好了。学生只需聚焦于数据结构本身。这是真实世界的代码组织方式。
>
> 2. **性能即分数**：不是"做对就行"，而是"做得最快才好"。学生天然有动力优化哈希函数和桶数量——这是算法课最难传递的动机，Speller 通过基准测试自然地解决了。
>
> 3. **143,091 个单词**：这个规模恰好介于"玩具数据"和"工业数据"之间。小到可以全部放入内存，大到足以暴露低效实现的性能问题。
>
> 4. **`valgrind` 检查**：内存泄漏检测被纳入评分标准。这教会学生：代码不仅要正确，还要干净。

- **缩进错误**：Python 对缩进敏感，混合 Tab 和空格会报错
- **`range()` 的边界**：`range(1, height + 1)` 而非 `range(1, height)`
- **DNA 中最长连续重复**：`"AGATC"` 在 `"AGATCAGATCAGATC"` 中是连续出现 3 次，不是总共出现 3 次

**设计亮点：**

> PSet 6 的核心教学意图是**对比教学法（contrastive learning）**。学生已经用 C 实现了这些程序，现在用 Python 再做一次。同一逻辑在两种语言中的表达差异（如 C 的 `for (int i = 0; i < n; i++)` vs Python 的 `for i in range(n)`）让语言特性在对比中清晰浮现。DNA 作为新题目则利用了 Python 的字符串处理优势——这种题目在 C 中实现相当繁琐，在 Python 中却顺滑自然。

## Week 7 — SQL

### Lab 7: Songs

**你要做什么：**

在一个包含 Spotify 歌曲数据的 SQLite 数据库中编写 SQL 查询。回答诸如 "Drake 有哪些歌？" "平均能量最高的前 5 首歌是什么？" 等问题。

**核心知识点：**

- **`SELECT`、`FROM`、`WHERE`**：基础查询
- **`LIKE` 模糊匹配**：`WHERE name LIKE '%love%'`
- **聚合函数**：`AVG()`、`COUNT()`、`SUM()`
- **`GROUP BY` + `HAVING`**：分组后过滤
- **`ORDER BY` + `LIMIT`**：排序 + 截取 Top N
- **`.schema`**：查看表结构

**常见坑：**

- **`WHERE` vs `HAVING`**：`WHERE` 在分组前过滤行，`HAVING` 在分组后过滤组
- **单引号 vs 双引号**：SQL 字符串用单引号 `'Drake'`
- **`LIMIT` 的位置**：在 `ORDER BY` 之后
- **嵌套查询的不必要性**：新手倾向于写嵌套 `SELECT`，但大多数情况下 `JOIN` 更清晰高效

**设计亮点：**

> Songs 是一个纯粹的 SQL 练习——不涉及任何宿主语言。在 SQLite 命令行中直接写查询，专注学习关系型数据库的核心：如何用声明式语言精确描述"我要什么数据"，而非"怎么取数据"。Spotify 数据集的真实性增加了投入感。

### Problem Set 7: Movies / Fiftyville

#### Movies（多表 JOIN 查询）

**你要做什么：**

在一个 IMDb 风格的电影数据库（`movies.db`）中编写 13 道 SQL 查询题，从简单的单表查询逐步推进到复杂的多表 JOIN。

数据库包含 5 个表：`movies`、`people`、`ratings`、`stars`、`directors`。

**典型查询：**

1. "列出 2008 年上映的所有电影" → 简单 SELECT
2. "列出所有评分 ≥ 9.0 的电影" → `JOIN movies + ratings`
3. "列出 Johnny Depp 和 Helena Bonham Carter 共同出演的电影" → 自 JOIN stars 表
4. "列出出演最多电影的人" → `GROUP BY + COUNT + ORDER BY + LIMIT 1`

**核心知识点：**

- **多表 `JOIN`**：`INNER JOIN` 是最常用的
- **表别名**：`FROM movies m JOIN ratings r ON m.id = r.movie_id`
- **自连接**：`JOIN stars s1 ... JOIN stars s2 ... WHERE s1.person_id != s2.person_id`
- **嵌套子查询**：`WHERE id IN (SELECT ...)`
- **`DISTINCT`**：去重
- **多排序**：`ORDER BY rating DESC, title ASC`

**常见坑：**

- **`ON` 条件的正确性**：写错 `ON` 条件会产生笛卡尔积（N×M 行）
- **`INTEGER` vs `TEXT`**：比较时类型要匹配（`year = 2008` 而非 `year = '2008'`，虽然 SQLite 可能容忍）
- **多个条件用 `AND`**：`WHERE year = 2008 AND rating >= 9.0`（不是 `year = 2008, rating >= 9.0`）
- **`ORDER BY` 多列**：`ORDER BY rating DESC, title ASC`——注意每列都有自己的升降序方向

**设计亮点：**

> Movies 的 13 道题是一条精心设计的**SQL 难度曲线**。从 `SELECT * FROM movies WHERE year = 2008` 到 "列出与 Kevin Bacon 出生同年的人中出演过最多电影的那位"，每道题在前一道的基础上增加一个概念。最后的题目需要组合 JOIN、GROUP BY、子查询、ORDER BY、LIMIT 全部技能。

#### Fiftyville（侦探式 SQL 推理）

**你要做什么：**

CS50 的小黄鸭被偷了！你要通过查询一个包含五十镇市民记录的 SQLite 数据库来破案。已知：盗窃发生在 2024 年 7 月 28 日 Humphrey Street。

你需要查出：
1. 小偷是谁
2. 小偷逃到了哪个城市
3. 帮凶是谁

**数据库包含表：**

- `crime_scene_reports`（犯罪现场报告）
- `interviews`（证人访谈）
- `atm_transactions`（ATM 交易记录）
- `bank_accounts`（银行账户）
- `airports`（机场）
- `flights`（航班）
- `passengers`（乘客）
- `phone_calls`（电话记录）
- `people`（人员信息）
- `bakery_security_logs`（面包店停车场出入记录）

**核心知识点：**

- **调查式推理链**：从犯罪现场报告 → 证人访谈 → 停车场监控 → ATM 记录 → 电话记录 → 航班预订
- **多步 SQL 查询**：每一步的查询结果为下一步提供输入
- **`datetime` 函数**：时间范围查询
- **复杂的多表 JOIN**：`people JOIN bank_accounts JOIN atm_transactions ON ...`
- **证据交叉验证**：停车场、ATM、电话三个独立线索必须指向同一个人

**常见坑：**

- **日期格式**：SQLite 中日期是 `YYYY-MM-DD`，犯罪日期是 `2024-07-28`
- **时间范围**：犯罪发生在上午 10:15，访谈提到停车场监控在 10:15-10:25 之间，ATM 在早上 10:15 左右，电话在 10:15 后约 10 分钟
- **访谈关键线索**：三个证人分别提到了停车场、ATM、电话三个线索——漏看任何一个都可能导致推理不完整
- **航班时间**：小偷乘坐了**最早**的次日航班
- **电话号码匹配**：电话记录中的 `caller` 和 `receiver` 需要和 `people` 表的 `phone_number` 关联
- **帮凶的确定**：小偷在盗窃后打了一个短电话（< 60 秒），接电话的人就是他/她的帮凶

**设计亮点：**

> Fiftyville 是 CS50 最受学生欢迎的作业之一。它不是传统的 SQL 练习题——它是**一个用 SQL 来解决的侦探故事**。学生通过一步步查询数据库来"审问证人"、"调取监控"、"追踪航班"。每一步 SQL 都有真实的案件推进意义，而不只是抽象的练习题。这个设计巧妙地将 SQL 学习包装成了沉浸式的角色扮演体验。

## Week 8 — HTML, CSS, JavaScript

### Lab 8: Trivia

**你要做什么：**

创建一个简单的问答互动网页。用户看到一道选择题，点击答案后显示对/错反馈，并自动显示下一题。

**核心知识点：**

- **HTML 结构**：`<div>`、`<h2>`、`<button>` 的使用
- **CSS 样式**：`.correct { background-color: green; }` 和 `.incorrect { background-color: red; }`
- **JavaScript DOM 操作**：`document.querySelector()`、`.addEventListener('click', ...)`
- **事件驱动编程**：点击按钮触发反馈
- **状态管理**：当前是第几题？用户选了什么？

**常见坑：**

- **选择器写错**：`document.querySelector('.correct')` 的 `.` 表示 class，`#` 表示 id
- **多个按钮共享事件**：需要用 `forEach` 给每个按钮绑定事件，或使用 `event.target`
- **CSS 优先级**：如果样式不生效，检查是否是其他选择器覆盖了

**设计亮点：**

> Trivia 是前端三件套（HTML/CSS/JS）的最小可行产品。只用了几个 `<div>` + `<button>` + 三行 JS，却实现了一个功能完整的互动页面。这种**极简起点**降低了前端心理门槛。

### Problem Set 8: Homepage

**你要做什么：**

用 HTML、CSS、JavaScript（和 Bootstrap 框架）创建一个个人主页。必须包含：至少 4 个不同页面、Bootstrap 组件、自定义 CSS、至少一个 JavaScript 交互功能。

**核心知识点：**

- **多页面站点**：`index.html`、`about.html`、`hobby.html` 等
- **Bootstrap 框架**：导航栏（navbar）、卡片（card）、网格系统（grid）
- **响应式设计**：`container`、`col-md-6` 等断点

## Week 9 — Flask

### Lab 9: Birthdays

**你要做什么：**

创建一个生日记录 Web 应用。功能：展示所有已保存的生日列表、添加新生日记录、删除已有记录。后端用 Flask + SQLite。

**核心知识点：**

- **Flask 路由**：`@app.route("/")`、`@app.route("/add", methods=["POST"])`
- **模板渲染**：`render_template("index.html", birthdays=birthdays)`
- **Jinja2 模板**：`{% for birthday in birthdays %}` 循环渲染
- **SQLite CRUD**：`INSERT INTO`、`SELECT * FROM`、`DELETE FROM`
- **POST 表单处理**：`request.form.get("name")`

**常见坑：**

- **GET vs POST**：添加和删除用 POST，查看用 GET
- **删除后的重定向**：POST 处理后应 `redirect("/")` 而非 `render_template`，防止刷新时重复提交
- **SQL 注入**：使用参数化查询（`?` 占位符）而非字符串拼接
- **表单 `name` 属性**：`<input name="name">` —— `request.form.get("name")` 中的名字必须匹配

**设计亮点：**

> Birthdays 是 Flask 的 "Hello World"。在一个问题中覆盖了 Web 应用的完整请求-响应循环：浏览器发请求 → Flask 路由处理 → SQLite 读写数据 → Jinja2 渲染模板 → 浏览器展示。这是理解 Web 开发全貌的最小闭环。

### Problem Set 9: Finance（股票交易网站）

**你要做什么：**

这是 CS50 最大的编程项目——一个完整的股票模拟交易网站。功能包括：

1. **注册/登录/登出**（密码哈希存储）
2. **Quote**：输入股票代码，查询实时价格（通过 IEX Cloud API）
3. **Buy**：用虚拟资金买入股票
4. **Sell**：卖出持有的股票
5. **Index**：展示用户持仓、总资产（现金 + 股票市值）
6. **History**：展示所有交易历史记录

**核心知识点：**

- **Flask Session**：`session["user_id"]` 跟踪登录状态
- **密码安全**：`generate_password_hash()` + `check_password_hash()`（Werkzeug）
- **SQL 多表操作**：`users` 表（现金）+ `transactions` 表（交易记录）+ `portfolios`（持仓汇总）
- **外部 API 调用**：`requests.get(f"https://api.iex.cloud/v1/...")`
- **JSON 解析**：`quote["latestPrice"]`
- **事务性操作**：买入 = 扣现金 + 增加持仓；卖出 = 加现金 + 减少持仓；两者必须原子化
- **`@login_required` 装饰器**：路由保护
- **表单验证**：前端 + 后端双重验证
- **浮点数精度**：金额用 `Decimal` 或存储为整数（美分）以避免浮点误差
- **Jinja2 过滤器**：`{{ price | usd }}` 自定义美元格式

**常见坑：**

- **现金不足时的拒绝**：买入前检查 `cash >= shares * price`
- **卖出超过持有量**：卖出前检查 `shares_owned >= shares_to_sell`
- **用户不存在**：登录时用户名和密码的先后检查顺序
- **密码确认**：注册时 `password == confirmation`
- **API 限流**：IEX 免费版有频率限制，开发时需要处理 `429 Too Many Requests`
- **SQLite 并发**：`db.execute()` 不是线程安全的，但 Flask 开发服务器是单线程的，所以实际上没问题
- **持仓汇总 vs 交易日志**：`portfolio` 是聚合视图（每只股票一行 + 总持有量 + 平均买入价），`history` 是原始交易记录（每笔买入/卖出各一行）

**设计亮点：**

> Finance 是 CS50 的 "毕业作品"。它整合了学生 9 周以来学到的所有技能：
> - C 语言锻炼的逻辑思维 → 设计 buying/selling 的交易逻辑
> - Python 的简洁语法 → Flask 路由的清晰表达
> - SQL 的查询能力 → 复杂的多表查询和聚合
> - HTML/CSS/JS → 用户界面
> - 内存管理的意识 → 为什么 Python 不需要手动 malloc
>
> Finance 还是一个**安全意识**的分水岭：密码哈希、SQL 注入防护、Session 管理——这些不再是抽象概念，而是学生在构建自己的应用时必须处理的实际问题。

## 总结：这些作业为什么能让你真正学会编程

CS50 的作业设计有六个核心原则，正是它们让这门课与众不同：

### 1. 从零实现，不给骨架（Speller 除外）

大多数编程课的作业让你 "填空"——`// TODO: 在此处写你的代码`。CS50 反其道而行之：给你一个空白的 `hello.c`，告诉你要求，让你从 `#include <stdio.h>` 开始写。

这意味着你**必须理解每一行代码**，因为你写了每一行代码。

### 2. 每道题都是一个"迷你现实世界问题"

不是 "写一个函数返回前 n 个质数"，而是 "从磁盘镜像中恢复被删除的 JPEG 照片"。不是 "实现一个排序算法"，而是 "实现一种真实国家使用的投票制度"。这种真实性让编程从 "做作业" 变成 "解决问题"。

### 3. 工具就是武器

`check50` 给你即时反馈（你的程序对所有测试用例都通过了吗？）。`style50` 教你写干净的代码（缩进、命名、注释）。`debug50` 让你学会调试（而不是 `printf` 大法）。CS50 教的是**软件工程**，不只是编程。

### 4. "Less" 和 "More" 的分层设计

没有 "所有人都必须完成最难题目" 的暴力要求。感到困难？选 Cash（贪心算法）。想要挑战？选 Credit（Luhn 算法 + 卡类型识别）。这个设计让不同起点的学生都能在 "最近发展区" 内学习。

### 5. 渐进式语言迁移

Scratch → C → Python → SQL → HTML/CSS/JS → Flask。每一步语言切换都有明确的**教学意图**：Scratch 建立程序思维，C 理解计算机底层，Python 感受高级语言的生产力，SQL 学会声明式思维，Web 技术栈学会构建完整应用。

### 6. 高峰体验设计

CS50 有几个精心设计的 "Wow Moment"：
- Mario 金字塔对齐的那一刻
- Recover 运行后突然出现 50 张 JPEG 的那一刻
- Speller 基准测试显示你的哈希表比教授的还快的那一刻
- Finance 第一次看到实时股价出现在自己网页上的那一刻

这些瞬间不是偶然的——它们是课程设计者为学习者埋下的 "里程碑奖励"。
